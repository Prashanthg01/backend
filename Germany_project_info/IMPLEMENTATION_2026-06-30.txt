2. COMPARATIVE ANALYSIS — TYPE 1 vs TYPE 2 SCHEDULER
   Files: backend/api/utils.py  |  views.py  |  tasks.py  |  urls.py
────────────────────────────────────────────────────────────────────────────────

PURPOSE
  Run both schedulers on the same product set simultaneously (in memory,
  nothing persisted to DB) and compute all 4 evaluation metrics for each,
  returning a structured side-by-side comparison with per-metric winners and
  an overall recommendation.

BACKEND — utils.py
  New function: compare_schedulers()
    Location: after compute_schedule_kpis() in section "4b. COMPARATIVE ANALYSIS"

  How it works:
    1. Materialise product list once (same list passed to both schedulers)
    2. Run run_shift_aware_scheduler()  →  record wall-clock time  →  compute KPIs + gaps
    3. Run run_job_shop_scheduler()     →  record wall-clock time  →  compute KPIs + gaps
    4. Build per-metric winner labels (lower_is_better flag per metric)
    5. Count quality wins per type across 4 metrics
    6. Return overall_recommendation string

  Return shape:
    {
      "type1": {
        scheduler, computation_time_seconds, makespan_hours, makespan_days,
        total_operations, machines_used, avg_utilization_pct,
        bottleneck_machine, bottleneck_util_pct,
        total_gaps, total_idle_hours,
        machine_utilization: { M1: %, M2: %, ... },
        per_machine_gaps:    { M1: { gaps, idle_hours }, ... }
      },
      "type2": { same structure },
      "delta": {
        makespan_hours_diff, avg_utilization_diff,
        total_gaps_diff, total_idle_hours_diff, computation_time_diff,
        winner_makespan, winner_utilization, winner_gaps,
        winner_idle_hours, winner_speed,
        type1_quality_wins, type2_quality_wins,
        overall_recommendation
      },
      "metadata": {
        products_compared, start_date,
        type2_local_opt_machines, type2_compaction_enabled
      }
    }

BACKEND — tasks.py
  New Celery task: compare_schedulers_task
    name: "compare_schedulers_task"
    Params dict: start_date, product_pks, local_opt_machines,
                 enable_compaction, batch_overrides
    Returns same shape as compare_schedulers() with status:"success" added

BACKEND — views.py
  New endpoint: compare_schedulers_view
    Route:  GET /api/compare-schedulers/
    Modes:  sync (default, runs inline) | async (?async_mode=true via Celery)
    Query params:
      start_date          YYYY-MM-DD          default: today
      product_pks         repeatable int      default: all products
      local_opt_machines  int                 default: 5
      enable_compaction   bool string         default: true
      async_mode          bool string         default: false
    Sync response  (200): full comparison dict
    Async response (202): { task_id, status, message, check_status_url }

BACKEND — urls.py
  path('compare-schedulers/', compare_schedulers_view, name='compare_schedulers')
  Import added to urls.py import block

3. EVALUATION METRICS PAGE — FRONTEND + BACKEND
   Files: frontend/app.py  (new page 8)
          backend/api/utils.py  (compare_schedulers — see section 2)
────────────────────────────────────────────────────────────────────────────────

PURPOSE
  New Streamlit page "📈 Evaluation Metrics" that visualises all 4 scheduler
  evaluation metrics in a side-by-side comparison of Type 1 vs Type 2.

THE 4 METRICS IMPLEMENTED

  ① Makespan
      Definition : max(end_hrs) − min(start_hrs) across all operations
      Unit       : hours and days
      Winner rule: lower is better
      Displayed  : bar chart (hours), bar chart (days), diff insight message

  ② Machine Utilization
      Definition : (machine busy hours / makespan) × 100 per machine; average
                   across all machines
      Unit       : percentage (%)
      Winner rule: higher is better
      Displayed  : average bar chart, per-machine grouped bar chart,
                   bottleneck callout boxes for both schedulers

  ③ Computational Time
      Definition : wall-clock seconds from scheduler call start to return
      Unit       : seconds
      Winner rule: lower is better
      Displayed  : bar chart, speed ratio metric (Type 2 is N× slower/faster),
                   explanatory caption about MILP overhead

  ④ Idle Gap Reduction
      Definition : count and sum of idle intervals (>1 min) per machine after
                   scheduling; uses count_schedule_gaps() from utils.py
      Unit       : gap count + idle hours
      Winner rule: fewer gaps is better
      Displayed  : total gaps bar chart, total idle hours bar chart,
                   per-machine grouped bar for idle hours

FRONTEND — SESSION STATE ADDITIONS
  'eval_result':   None   — stores latest comparison API response
  'eval_task_id':  None   — Celery task ID for async mode

FRONTEND — NAVIGATION
  Added "📈 Evaluation Metrics" to the sidebar radio (position 8)

FRONTEND — PAGE LAYOUT

  Controls row (4 columns)
    Schedule Start Date     date_input   (key: em_start_date)
    Type 2 MILP Machines    slider 0-15  (key: em_local_opt)
    Type 2 Compaction       checkbox     (key: em_compaction)
    Run in background       checkbox     (key: em_async)
  Run Comparison button     primary, full width

  Async poll section
    Shows task ID, "Check Status" button, progress % feedback

  Empty state
    Placeholder with ⚖️ icon and instructions

  Recommendation Banner
    Color: green  = Type 2 wins overall
           blue   = Type 1 wins overall
           purple = tied
    Shows per-type quality win count and metadata

  Metric Scorecards  (3-column table)
    Col 1: metric name + winner chip (color-coded badge)
    Col 2: Type 1 value (dark-blue card, monospace font)
    Col 3: Type 2 value + delta with directional color (dark-green card)
    Delta color: green = improvement, red = regression, grey = neutral

  Charts  (4 tabs)
    Tab "📏 Makespan"      : hours bar | days bar | insight message
    Tab "📊 Utilization"   : avg bar | per-machine grouped bar | bottleneck boxes
    Tab "⏱️ Compute Time"  : bar chart | speed ratio metric cards + caption
    Tab "🕳️ Idle Gaps"     : gap count bar | idle hours bar |
                              per-machine grouped bar | insight message

  Summary Table
    Pandas DataFrame with columns: Metric | Type 1 | Type 2 | Δ (T2−T1) | Winner
    Download button: "📥 Download Comparison CSV" → evaluation_metrics.csv

5. DATA FLOW SUMMARY
────────────────────────────────────────────────────────────────────────────────

  User clicks "Run Comparison" in frontend
        │
        ▼
  GET /api/compare-schedulers/?start_date=...&local_opt_machines=5
        │
        ▼
  compare_schedulers_view (views.py)
    - Validates products and process steps exist in DB
    - Sync: calls compare_schedulers() inline
    - Async: dispatches compare_schedulers_task via Celery
        │
        ▼
  compare_schedulers (utils.py)
    - Products materialised once
    - run_shift_aware_scheduler()  → rows1, time1
    - compute_schedule_kpis(rows1) → kpis1
    - count_schedule_gaps(rows1)   → gaps1
    - run_job_shop_scheduler()     → rows2, time2
    - compute_schedule_kpis(rows2) → kpis2
    - count_schedule_gaps(rows2)   → gaps2
    - Compute deltas and winner labels
    - Return structured dict
        │
        ▼
  Frontend receives JSON
    - Renders recommendation banner
    - Renders 4 metric scorecards
    - Renders 4 chart tabs
    - Renders summary table + CSV download
